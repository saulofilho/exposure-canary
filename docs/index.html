EXPOSURE CANARY v0.1.0

The record changes when someone touches the canary.

Exposure Canary creates a token on an asset you control: a URL, a DNS name, or an email address. When your collector stores a hit, the tool imports the JSON, folds repeats, and writes a report.

The report keeps the time, the kind, the asset, and the source your collector sent. A person and an intent stay out of it. The collector remains a host you operate.

Code: github.com/saulofilho/exposure-canary

Three canaries, one registry.

KindValueYou control
URLhttps://<collector>/c/<id>the https host
DNS<id>.<zone>the zone
Emailcn-<hex>@<domain>the mailbox

One canary per surface. The label names the surface that was touched. Create requires --owned: your confirmation that the asset is yours.

.exposure-canary/state.json holds the ids. Keep it out of git.

CLI

uv pip install -e ".[mcp]"

exposure-canary create \
  --kind url --label page --asset site \
  --collector https://collect.example --owned

exposure-canary import-webhook webhook.json
exposure-canary report -o report.md

DNS takes --zone. Email takes --domain. A webhook accepts canary_id, observed_at, and source. The same canary, the same source, and the same 5-minute window count once.

Cursor plugin

Three tools: create_canary, import_webhook, render_report.

The exposure-canary skill stays on an asset you own, says where to plant the value, and stops when the request leaves defense.

The server starts with uv on PATH, from the repository root.

uv run --extra mcp python -m exposure_canary.mcp_server
